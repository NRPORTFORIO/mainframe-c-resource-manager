# mainframe-c-resource-manager

## プロジェクト概要
社会インフラを支える金融メインフレーム（勘定系基盤）のデータ処理思想を取り入れた、C言語によるリソース最適化・堅牢性検証シミュレーターです。
大量のトランザクション（取引データ）を、サーバーの限られたメモリリソースの中で「1ミリ秒でも速く、安全に、1円のズレもなく」処理するためのロジックを実装しています。

## 開発の背景と目的
NTTデータグループの歓迎条件にある「サーバーやメインフレームに関する知識・経験」への意欲を示すために作成しました。
実務未経験ながら、大型コンピューターやインフラエンジニアに求められる「リソースの最適化（省メモリ・高速化）」や「アベンド（システム異常終了）の防止」といった設計思想をコードレベルで理解していることを証明するポートフォリオです。

## 技術的アプローチとメインフレーム思想の再現
1. **固定長構造体によるメモリ断片化（フラグメンテーション）の防止**
   - 動的なメモリ割り当てを排除し、固定長配列（`char account_id[17]`）を使用することで、メインフレームの安定稼働に不可欠な「メモリ空間の予測可能性」を担保しています。
2. **ポインタ（アドレス参照）による超高速処理**
   - データを関数に渡す際、メモリのコピー（無駄なリソース消費）を発生させないよう、ポインタを用いてメモリ上の実データを直接安全に更新します。
3. **ビット演算による高速なステータス管理**
   - 口座の状態（ロック等）を1バイト内のビットフラグ（`unsigned char`）で管理し、サーバーのCPU負荷を最小限に抑える超高速なバリデーションを実現しています。

4.【NEW】Pythonによる運用自動化（AIOps）の統合log_analyzer.py: C言語基盤が出力するシステムログをPythonでリアルタイムにパースし、エラーやシステム異常終了（アベンド）の兆候を自動検知するスクリプトを追加。インフラの「安定稼働」と運用の「自動化・効率化」を両立するモダンな運用保守を意識しています。

## 技術スタック・アーキテクチャ

### 1. コア・データ処理基盤（C言語レイヤー）
- **言語**: C言語 (C11準拠)
- **主要概念**: 固定長構造体によるメモリ最適化、ポインタ制御によるアドレス参照、ビット演算による超高速バリデーション、厳格なエラーハンドリング（アベンド防止）
- **役割**: 1円のズレも許されない金融メインフレーム（勘定系基盤）の堅牢なデータ処理思想の再現

### 2. 運用自動化・ログアナリティクス（Pythonレイヤー）
- **言語**: Python (3.x)
- **主要ライブラリ**: os, re (正規表現), datetime
- **主要概念**: ログパース、リアルタイム異常検知、自動アラートシステム、AIOps（運用効率化）の思想
- **役割**: コアシステムが出力する大量のシステムログを自動解析し、障害の予兆（アベンドの危険性）を検知・レポートする運用の自動化
